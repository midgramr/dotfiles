# S3 workflows

Use these instructions for S3 listing, metadata, transfers, versions, and access diagnosis. Replace uppercase placeholders; append the established `--profile PROFILE --region REGION` to commands. Check operation help when choosing flags.

## Find objects and inspect metadata

Use `s3` for convenient transfers and `s3api` for structured results. Split `s3://bucket/path/file` into bucket `bucket` and key `path/file`; do not include a leading slash in the key unless it actually exists. Prefix `data/` differs from `data` (which also matches `database`). Shell wildcards in S3 URIs are not object selectors.

```bash
aws s3 ls s3://BUCKET/PREFIX/
aws s3api list-objects-v2 --bucket BUCKET --prefix PREFIX/ --delimiter / --output json
aws s3api list-objects-v2 --bucket BUCKET --prefix PREFIX/ --output json
aws s3api head-object --bucket BUCKET --key KEY --output json
```

`--delimiter /` groups nested keys into `CommonPrefixes`; omit it for every matching key. Inspect `Contents` for object metadata. Narrow the prefix before listing a large bucket, and keep pagination enabled for inventories. Listing reports current objects, not historical versions or delete markers. An empty listing alone does not establish why expected data is missing.

For a complete prefix count and byte total, save paginated JSON and aggregate locally:

```bash
aws s3api list-objects-v2 --bucket BUCKET --prefix PREFIX/ --output json > objects.json
jq '{count: ((.Contents // []) | length), bytes: ([.Contents[]?.Size] | add // 0)}' objects.json
```

Check the AWS command succeeded before interpreting its output. This materializes the listing locally; for very large inventories consider an existing S3 Inventory report rather than scanning the bucket repeatedly. State scope and truncation. `LastModified` is object modification time, not necessarily the data's business date. ETags are not universally MD5 hashes, particularly for multipart uploads and some encryption modes.

## Read data without unnecessary downloads

```bash
aws s3 cp s3://BUCKET/KEY ./local-file --no-progress
aws s3api get-object --bucket BUCKET --key KEY --range bytes=0-65535 ./sample.bin
```

`get-object` writes bytes to its required output filename and prints response metadata separately. A byte range is useful for headers or plain text but does not generally produce a readable slice of compressed or columnar data. Use metadata and file format to choose a suitable reader. Stream `aws s3 cp s3://BUCKET/KEY -` only for known, bounded content; do not flood tool output with binary data or secrets. Fetch a named `--version-id` when the task requires a specific version.

## Copy and sync

```bash
aws s3 cp ./local-file s3://BUCKET/KEY --dryrun
aws s3 cp s3://BUCKET/PREFIX/ ./download/ --recursive --exclude '*' --include '*.json' --dryrun
aws s3 sync ./output/ s3://BUCKET/PREFIX/ --dryrun
aws s3 sync s3://SOURCE_BUCKET/PREFIX/ s3://DEST_BUCKET/PREFIX/ --source-region SOURCE_REGION --region DEST_REGION --dryrun
```

Inspect the preview, then remove `--dryrun` to perform the requested transfer. Later include/exclude rules override earlier matching rules; quote patterns so the shell does not expand them. `--include` alone does not exclude other files: use `--exclude '*'` first when selecting only matching files.

Check destination key layout and trailing slashes in the preview. `cp --recursive` copies matching entries; `sync` skips entries according to its comparison rules, which are not a general content-hash comparison. Consult help before selecting `--size-only`, `--exact-timestamps`, or checksum options. Local uploads can follow symlinks; inspect that behavior and use `--no-follow-symlinks` when linked targets should not be uploaded.

`sync --delete` also removes destination objects absent from the source; excluded entries are excluded from deletion. Add it only when deletion is part of the request. `mv` copies and removes the source, so do not substitute it for `cp`. Preserve intended encryption, metadata, tags, and storage class; consult copy-property options when those matter. Do not add public ACLs or force archival retrieval as incidental transfer fixes.

After transfer, inspect command exit status and verify the expected destination keys and sizes or relevant checksums. A preview proves selection, not write permissions or successful completion.

## Versions, deletion, and access failures

```bash
aws s3api get-bucket-versioning --bucket BUCKET
aws s3api list-object-versions --bucket BUCKET --prefix KEY --output json
aws s3api get-object --bucket BUCKET --key KEY --version-id VERSION_ID ./restored-file
aws s3 rm s3://BUCKET/PREFIX/ --recursive --dryrun
```

The versions prefix can match more than the exact key; filter the returned `Key` before choosing a version. On versioned buckets an ordinary delete normally creates a delete marker; deleting a specific version permanently removes that version. Do not turn a request to remove current objects into a purge of all versions. For batch deletion, check `delete-objects help`, build an exact JSON object list, obey the request size limit, and inspect per-object `Errors` even when the API request succeeds.

For access failures, distinguish the calling identity, bucket region, bucket/key spelling, bucket policy, and KMS key access. `head-object` may return 403 rather than 404 for a missing object when the caller cannot list the bucket; do not treat every 403 as proof the object exists. Listing access does not imply object-read or KMS-decrypt access. Use `--request-payer requester` only for an intended Requester Pays operation. Diagnose with metadata and existing configuration before changing policies.
